## 1 · Findings

### MAJOR-1 — the guard wraps only the `await`, so a strategy fault one line later is still bot-fatal — and still kills every strategy behind it

**Evidence** — `src/core/system_controller.py:1741-1761`. The `try` covers exactly one
statement, `decision = await strat.on_new_candle(...)`. Everything that *dereferences
that strategy's own output* sits outside it, inside the same `for strat in active`
loop:

- `:1767-1768` — `decision['signal']`
- `:1773` — `self.signal_grader.grade(decision, ctx, enriched_df.iloc[-1])`
- `:1776-1777` — `decision['signal']`, and `float(decision[k]) for k in ('price','sl','tp')`
- `:1786` — `await self._execute_signal(...)`
- `:1795-1796` — `decision['type']`, `float(decision['price'])`, `['sl']`, `['tp']`

A strategy that returns a malformed decision dict has not "raised on this bar" in the
guarded sense, but it produces exactly the failure this session exists to eliminate.
Verified against the session's own fixtures:

```python
bad = Survivor(name="BadShape", decision={"signal": "BUY", "type": "MARKET", "price": 1.1})
ok  = Survivor(name="Downstream", decision=None)
c   = make_controller([bad, ok], telemetry=FakeTelemetry())
run(c._run_strategies("EURUSD", _bar_df(), tf="H1"))
# -> B1 ESCAPED: KeyError 'sl'
#    downstream strategy calls: []
```

The exception escapes `_run_strategies` entirely → reaches `run()`'s handler at
`:639-642` → `FATAL SYSTEM CRASH` + `raise` → loop dead, in-trade management dead for
every open position on every symbol. `ok.calls == []` shows the second strategy on
that bar never ran either — the same "a `return`-on-error would silently cost every
strategy behind it" hazard the session's own
`test_later_strategies_still_run_this_bar` was written to prevent, just moved five
lines down.

This directly contradicts the commit message's claim ("Now the blast radius is (this
strategy, this symbol, this bar)") and the in-code comment at `:1750-1752` ("The blast
radius must be this strategy, this symbol, this bar"). For the class of faults
originating in the strategy's *output* rather than its *body*, the blast radius is
still the whole bot. The backlog row's stated fix is "per-strategy try/except" — the
per-strategy unit of work is the loop body, not the first line of it.

Not hypothetical for this codebase: the same audit sweep that produced D6 recorded
`Gambit Judas structurally dead (Timestamp TypeError)`, i.e. strategies here do emit
shapes the controller was not written for. `SilverBullet` happens to always return a
full dict, which is why this is MAJOR and not CRITICAL.

**Fix** — move the `except` to cover the loop body: `try:` at the top of
`for strat in active:` through `pending_meta[id(intent)] = ...`, with the existing
handler. `continue` already has the right meaning there. Note that `_execute_signal`
would then also be inside the guard, which is a behaviour change worth being
deliberate about (it currently has its own internal gating); if that is undesirable,
guard `:1743`–`:1783` and leave the two dispatch calls out, but say so in a comment.
The test to add is the probe above: a strategy whose decision is missing `sl` must be
journalled and skipped, and a later strategy on the same bar must still run.

### MINOR-1 — the new bias/liquidity WARNINGs land in neither of the two places the operator reads

**Evidence** — `src/analysis/bias_engine.py:16` and `src/analysis/liquidity.py:16`
create loggers named `src.analysis.bias_engine` / `src.analysis.liquidity`. The
project's only logging configuration is `AuditLogger._setup_logging`
(`src/core/audit_logger.py:66-83`), which attaches its `RotatingFileHandler` to the
logger named **`"TitanBot"`** — a sibling hierarchy. There is no `basicConfig` and no
root handler anywhere in `src/` or `main.py` (`grep -rn "basicConfig\|logging.disable" src/ main.py` → no hits;
uvicorn's `dictConfig` at `src/ops/web/server.py:213` configures the `uvicorn.*`
loggers, not root). Verified end to end in a scratch cwd with a real `AuditLogger`
constructed first:

```
titan_system.log contains 'baseline event': True
titan_system.log contains bias warning   : False
root logger handlers                     : []
audit_log DB rows mentioning the fault   : 0
```

The record is emitted only by `logging.lastResort` → bare stderr. So the fault is
absent from `data/logs/titan_system.log` and from the `audit_log` SQLite table — the
two durable artifacts every other Titan diagnostic goes to — and survives only if the
process happens to have been launched with stderr redirected. On an unattended
forward test that is the difference between "visible" and "visible in principle",
which is the exact distinction this session was opened to fix.

The unit tests assert on the logger object (`assertLogs("src.analysis.bias_engine")`),
so they pass regardless of where — or whether — the record is ever handled. They
cannot catch this.

**Fix** — one word each: `logging.getLogger("TitanBot." + __name__)`, which inherits
the rotating file handler and puts these lines in the same stream as every other
event. (Attaching a root handler in `_setup_logging` would also work and would fix
`src/ops/web/server.py:22` at the same time, but is a wider blast radius than this
session should take.) Whichever is chosen, add a test that the record reaches a
handler, not just a logger.

## 2 · Checked and found clean

- **No out-of-scope files.** 5 files, all named by the backlog row; no config, no docs,
  no build artifact committed.
- **`except Exception` does not swallow cancellation** — `asyncio.CancelledError` is a
  `BaseException` on 3.10+, so `/panic` and shutdown still propagate.
- **The alert cannot itself become the fatal path.** `Telemetry.send_message`
  (`src/ops/telemetry.py:81-85`) only `create_task`s; all network failure is contained
  inside `_async_send_retry`. So `await self._alert_strategy_fault(...)` inside the
  `except` block cannot re-raise and defeat the containment it is reporting.
- **Throttle dict growth is bounded** by |strategies| × |pairs| (12 pairs × 3
  strategies today). No leak.
- **Throttle is never re-armed on recovery** — deliberate and consistent with
  `DD_CANCEL_ALERT_INTERVAL_S` (`:128-129`); a flapping strategy costs one Telegram per
  30 min per pair, which is the right trade.
- **Markdown hardening is correct**: truncate → replace backtick → collapse whitespace,
  in that order, so no partially-escaped tail can be produced.
- **The `assertNoLogs` control cases are real** — `test_healthy_path_logs_nothing` and
  `test_legitimate_empty_returns_log_nothing` pin that the two legitimate `{}` returns
  (short history, flat range) stay silent, which is what keeps the new WARNING from
  being tuned out.
- **Trading behaviour is unchanged** by the D7 half, and pinned as such
  (`test_fallback_value_is_unchanged` on both engines).
- Trivia, not findings: both analysis files still end without a trailing newline
  (pre-existing); the `run()` helper leaks an unclosed event loop per call, emitting
  `ResourceWarning` noise into the suite — but that pattern is established in ~10
  existing `tests/unit` modules, so it is house style, not a regression.

## 3 · Three-axis readiness

- **Does it work?** Partly. The D7 half works as a code change but its output does not
  reach an operator-visible sink (MINOR-1). The D6 half works for the failure mode it
  guards and is well tested, but leaves an adjacent, equally fatal failure mode open
  (MAJOR-1).
- **Is it safe?** Yes. Nothing here can move money: fallback values are unchanged and
  pinned, the new code paths are log/alert only, and the containment is strictly
  additive. There is no regression risk in what shipped — the findings are all about
  what did not ship.
- **Is it worth it?** Yes, clearly — this closes a real single-point-of-failure on a
  live forward test, and the test file raises the bar for the next session. The
  remediation is small: move one `try` boundary and rename two loggers.
