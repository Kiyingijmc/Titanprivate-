## 2. Premise re-confirmed in the live tree

- `TradeManager.sync_positions` has exactly **one** caller in the whole tree
  (`src/core/system_controller.py:919`). Before this commit `PAUSED` therefore meant *zero*
  in-trade management: no break-even, no partials, no runner trail, no time-exit, and no
  emergency kill-switch (`src/execution/trade_manager.py:137-172`).
- `PAUSED` is reachable from two independent places: the operator
  (`set_system_pause`, `system_controller.py:1460-1464`) and the stale/blackout news
  auto-pause (`_check_news_status`, `:1182-1186`). The second is not hypothetical — this
  project has already seen the news feed drop out on a WSL DNS flap.
- Nothing compensated. The 60 s jobs that keep running while paused
  (`_perform_reconciliation`, `_cleanup_ghost_orders` `:969-978`) only reconcile DB rows and
  cancel *pending* orders; neither touches an open position's SL.

So the defect is real and is the one the 2026-08-07 full-system audit recorded
("PAUSED freezes in-trade management"). Premise good.

## 4. Is the fix complete, and complete *only* where it should be?

**Complete.** `grep -n 'BotState\.'` gives `:95`, `:450`, `:455`, `:916`, `:925`, `:1182-1188`,
`:1453`, `:1462`, `:1497`. Only `:916` and `:925` gate per-tick work. There is no second
freeze point, so the one-state widening is the whole fix.

**Reaches the live path end-to-end.** Every input management needs is refreshed on an
ungated path while paused:

- `current_open_positions` / `current_pending_orders` ← `HEARTBEAT` branch (`:944-945`), ungated. ✅
- `live_prices` ← `TICK` prologue *above* both gates (`:905`). ✅
- `state_manager.backfill_position_state` (`:965-967`) ungated, so `initial_entry`/`initial_tp`
  still fill while paused — the ratchet can engage for the **first** time during a pause.
- `run()`'s `while True` (`:483-513`) has no state gate anywhere, so ticks keep being polled
  and routed while paused. ✅ (I read the loop; sections A–F are all unconditional on state.)

**No new risk can open while paused.** `_dispatch_mgmt_command` (`:766-814`) emits only
`MODIFY`, `CLOSE_POS`, and `CLOSE_POS`+volume. `_execute_signal` has exactly two callers, both
inside `_run_strategies` (`:1118`, `:1152`), whose only caller is `:934` — behind the still
`ACTIVE`-only gate. `_run_strategies` is otherwise reachable only from
`src/research/kernel_replay.py:144`, which builds its own controller and never calls
`_process_incoming_data`. The comment at `:923-924` does not overclaim.

**Ordering swap is harmless.** Management now runs *before* `process_tick` (it used to run
after). `sync_positions` reads only `live_prices` (set at `:905`) and `current_open_positions`
(set on `HEARTBEAT`) — never the candle buffer — and `_process_incoming_data` is awaited
serially from the single main loop, so no coroutine mutates `market_data` across the awaits
in `_dispatch_mgmt_command`. Management still precedes `_run_strategies`, as before.

**The comment's `_readiness()` analogy is accurate.** `:1453` gates on exactly

## 5. Adversarial pass on the safety envelope

1. **Does this match the project's own stated pause contract, or bend it?** It matches, and
   the *old* behaviour was the violation. `docs/trading-bot-brainstorm/05-interfaces-validation-ops-learning.md:59`
   defines the red button as "PAUSE-ALL (**no new risk**)", and
   `docs/trading-bot-brainstorm/brainstorm-v2/pass3-systems.md:181` is explicit: breakers
   "block only … entry actions; **resting cancels and exits still run** (02§A4: never block
   exits)". A pause that froze exits was the design-doc breach; this commit closes it.
2. **Can a paused bot now take a non-protective action?** One, and it is defensible. With
   `runner.enabled: true`, the `Ratchet L3` MODIFY sends `tp = 0.0`
   (`src/execution/trade_manager.py:216-219`) — it *removes* the take-profit. That is
   variance-increasing. But the same single `MODIFY` sets SL to the L2 price, a floor at
   ~61.8 % of range **in profit**, and the two cannot be separated. Freezing instead leaves
   the original stop and no BE at all — strictly worse. Not a defect.
3. **Is management-while-paused visible to the operator?** Yes. Every `Ratchet L1/L2/L3` and
   every `Risk Guard` close fires a Telegram via `notify_management`/`notify_partial`
   (`:802`, `:808`, `:814`). `Runner Trail` MODIFYs are excluded (`:786`) — pre-existing,
   identical while `ACTIVE`, and only ever tightens a stop already in profit.
4. **Does this widen the blast radius of known open-loop defects?** Yes, and I want that on
   the record even though I am not charging it here. `sync_positions` persists the new
   ratchet level (`trade_manager.py:223-225`) *before* the command is dispatched
   fire-and-forget, and EA rejects are invisible to Python; likewise a frozen price feed with
   live heartbeats is undetected (`docs/sessions/_BACKLOG.md`, `exec-07-a-frozen-price-feed`).
   Both now apply in `PAUSED` as well as `ACTIVE`. Neither is created here, and the `ACTIVE`
   exposure — which also *opens* trades on the same bad inputs — strictly dominates.
5. **Does any doc now contradict the code?** No; it got *less* wrong.
   `docs/TRADE_MANAGEMENT.md:45` says management runs "on every tick", which was false before
   this commit and is closer to true after. No operator-facing string promises that pause
   halts management.

### No CRITICAL or MAJOR findings.

Three observations a remediation pass does **not** need to act on:

- **OBS-1 — `EMERGENCY` remains frozen, and the new comment (`:914-915`) states that as
  settled without arguing it.** The session's own rationale applies verbatim there:
  `trigger_panic` (`:1496-1501`) fires `CLOSE_POS` fire-and-forget with no verification, and
  EA rejects are invisible to Python — so a panic that fails to flatten (market closed,
  retcode 10018) leaves an open, permanently unmanaged book. The escape hatch is real but
  undocumented and counter-intuitive: `set_system_pause(True)` sets `PAUSED` *including from
  `EMERGENCY`*, so `/pause` after a failed panic un-freezes management. Pre-existing, outside
  S019's single-task scope, belongs in the backlog — correctly not in this diff.
- **OBS-2 — a paused bot still builds no candles.** A long pause leaves a hole in the
  `CandleMaker` buffer and the first post-resume bar stitches onto a stale predecessor.
  Unchanged by this commit (`process_tick` was `ACTIVE`-only before and after). Worth noting
  that the comment at `:923-924` frames "builds no candles" as the mechanism suppressing
  entries, when the `:925` gate on `_run_strategies` is what actually does that work; not
  building candles is a side effect with a cost, not the safeguard.
- **OBS-3 — test fidelity, cosmetic.** The fixture `TICK` (`test_...py:96`) has no `t` key,
  which the real `MultiTimeframeStore.process_tick` requires. It works only because
  `RecordingMarketData` is a stand-in — the right stand-in for these assertions, but the test
  would not survive being re-pointed at the real buffer.

## Three-axis readiness

- **Does it work?** Yes. The gate is correct and minimal; the fix is complete (only two
  `self.state` sites gate per-tick work and the right one moved); it reaches the live path
  end-to-end because every input management needs is refreshed on ungated paths and the main
  loop never checks state; and the new test was seen genuinely red on `main` and green here
  by me, not by report.
- **Is it safe?** Yes. Nothing reachable while `PAUSED` can open new risk — traced every
  caller of `_execute_signal` and every action `_dispatch_mgmt_command` emits. The one
  non-purely-protective action (L3 releasing the TP under `runner.enabled`) ships with a
  locked-in-profit floor and is inseparable from the stop it advances, and every management
  action while paused Telegrams the operator on the same channel they paused from.
- **Is it worth it?** Yes, and it is the clearest axis. It removes a live-money failure mode
  of exactly the 08-03 stopless-GBPJPY shape, closes a named full-system-audit defect, and
  brings the code back into line with the project's own locked design rule that exits are
  never blocked — for 13 added / 4 removed source lines and one focused test module. The
  builder did not touch `EMERGENCY`, the candle gate, or the operator surface, all of which
  were adjacent and tempting. Scope discipline on the *source* change is exemplary; the only
  thing standing between this branch and a clean merge is two files that should never have
  been added to it.
