## Does it work? (trace)

**`tradebot/core/clock.py`** — `LiveClock` anchors `time.monotonic_ns()` to `time.time_ns()`
once at `__init__` (`:42-44`) and derives `now_ns()` purely from the monotonic delta
(`:46-47`), never re-reading wall time after construction. This is exactly F-033's "comparisons
inside the core use monotonic; wall time only at edges" and pass3 §8.3's NTP-disciplined
wall-clock anchoring — the module's own docstring (`:6-10`) correctly scopes NTP *offset
monitoring* out to the not-yet-built `ops/health.py` (pass3 §8.3, Pass 6), which I confirmed
against the spec text rather than taking on faith. `test_now_ns_survives_a_backward_wall_clock_jump`
(`tests/unit/test_tradebot_clock.py:30-40`) and `test_now_ns_is_wall_clock_shaped_at_construction`
(`:42-50`) both trace correctly against the implementation: the former proves the class never
re-reads `time.time_ns`/`time.time` after construction (mocking them to `0` has zero effect on a
later `now_ns()` call), the latter proves the anchoring arithmetic itself is right.

`SimClock` (`:57-91`) is a min-heap scheduler keyed `(ts_ns, insertion_token, cb)` — the
insertion-order tiebreak (`itertools.count()`, `:62`, `:70`) makes same-timestamp firing order
deterministic, which `test_fires_in_ts_then_insertion_order` and
`test_reproducible_across_two_fresh_instances` (`:64-79`) both verify directly against two
independently-built schedules. `test_never_touches_the_wall_clock` (`:81-91`) patches
`time.time`/`time.monotonic`/`_ns` variants to raise `AssertionError` on any call and the
schedule still fires correctly — this is a real, teeth-having test, not a tautology: it would
fail loudly if `SimClock` ever leaked a wall-clock read. Cancellation (`:99-106`) and backward-advance
rejection (`:108-111`) both match the implementation (`_cancelled` set checked before firing,
`ValueError` on `ts_ns < self._now_ns`).

**`tradebot/core/events.py`** — the `Envelope` dataclass (`:153-165`) carries every field pass3
§1.1's table assigns to this layer (`event_id`/`schema`/`schema_version`/`ts_event`/`ts_ingest`/
`correlation_id`/`parent_ids`/`idempotency_key`/`actor`/`payload`/`seq`) and correctly omits only
`prev_hash`/`row_hash`, which the module's own docstring (`:6-9`) attributes to `event_log.py`
(M0-3, the sole writer) — matching pass3 §1.4's log-ownership split. `uuid7()` (`:31-45`) lays
out the 128-bit value as `[48-bit ts_ms][4-bit version=0111][12-bit rand_a][2-bit variant=10]
[62-bit rand_b]`, left-shifted by 80/76/64/62/0 respectively with no bit overlap — I hand-checked
the shift arithmetic bit-range-by-bit-range and it is RFC 9562-correct; the regex test
(`tests/unit/test_tradebot_events.py:34-36`) pins exactly this shape. `canonical_json` (`:55-92`)
sorts dict keys recursively (`:73`), rejects `NaN`/`Infinity` (`:82-83`), collapses `-0.0` to `0`
(`:84-85`), and emits int-valued floats as bare ints (`:86-87`) — all F-038 requirements, each
with a corresponding test (`tests/unit/test_tradebot_events.py:44-69`). The registry
(`register`/`register_upcaster`/`upcast_payload`, `:104-144`) and the envelope round-trip
(`envelope_to_dict`/`envelope_from_dict`/`encode_envelope`/`decode_envelope`, `:168-207`)
compose correctly: `decode_envelope` upcasts the payload to the schema's current registered
version before reconstructing the `Envelope` (`:186`), which
`test_v1_payload_upcasts_to_v2_shape_through_the_registry` (`tests/unit/test_tradebot_events.py:114-144`)
exercises end-to-end through the public encode/decode path, not by calling the registry
internals directly.

**Acceptance criterion, verbatim from the backlog** (`docs/sessions/_BACKLOG.md:15`): *"same-input
determinism, identical stream twice => identical serialization."*
`test_reproducible_across_two_fresh_instances` (clock) and

## Findings

### MINOR — `TestUpcasting` permanently mutates the module-global schema registry, with no cleanup

`tests/unit/test_tradebot_events.py:118-130` calls `@register(schema, 1)`, `@register(schema, 2)`,
and `@register_upcaster(schema, 1)` for `schema = "test.upcast_demo"`. These decorators write
into `tradebot.core.events._REGISTRY` / `_CURRENT_VERSION` / `_UPCASTERS`
(`tradebot/core/events.py:99-101`), which are process-lifetime module globals with no
`tearDown`/`addCleanup` removing the entries afterward.

**Failure scenario:** this is exactly the shape of bug this repository has already been bitten
by once — the Plan-06 `test_research_run` flake was diagnosed as global spec-state leaking
across test files under `unittest discover` (per project history; S002's fix addressed the
symptom without needing a teardown only because that module turned out to hold no such state).
Here the state genuinely is global and genuinely is written by a test. Today nothing collides
because `tradebot.core.events` has exactly one test file. The very next dependent sessions
(`m0-3-tradebot-core-event-log`, `m0-4-tradebot-core-projection-py`, per
`docs/sessions/_BACKLOG.md:16-18`) will add more test files importing this same module; if any
future test happens to reuse the literal string `"test.upcast_demo"` (or any schema name this
one registers), or asserts on `current_schema_version` for an unrelated schema after this test
has run first in discovery order, the two tests will silently interact. **Cheap fix:** snapshot
and restore the three module dicts in `setUp`/`tearDown` (or `addCleanup`), the same shape of
fix the module's own architecture will need anyway once real strategy/feature schemas are
registered at import time.

### MINOR — `Envelope` is a frozen dataclass with an unhashable `payload: dict` field

`tradebot/core/events.py:153-165`. `@dataclass(frozen=True)` auto-generates `__hash__` from all
fields unless told otherwise, but `payload` (and, for the "no correlation" case, `parent_ids` is
fine as a tuple) is a plain `dict`, which is unhashable. `hash(Envelope(...))` will raise
`TypeError: unhashable type: 'dict'` the first time anything tries to put an `Envelope` in a
`set` or use one as a `dict` key.

**Failure scenario:** `core/bus.py` (M0-5, `docs/sessions/_BACKLOG.md:18`) is the next consumer
of this exact type per pass3 §2.1/§6.1, and in-memory pub/sub buses commonly dedup or index
delivered events by identity — the moment that code reaches for a `set`/dict-key of envelopes
(even transiently, e.g. a "already-delivered" guard), it will crash. Not exercised by anything
in this session's own tests, so it is latent rather than demonstrated, but it is a landmine
placed directly in the path of the very next dependent milestone.

### MINOR — `LiveClock.call_at` has no test coverage

`tradebot/core/clock.py:49-54`. Every `SimClock` behavior (ordering, cancellation, backward-advance
rejection, wall-clock isolation) has a direct test; `LiveClock.call_at`'s real
`threading.Timer`-based scheduling and its `cancel` handle do not. The backlog's acceptance
line is scoped to determinism/serialization (which this method has no bearing on), so this is
not a DoD gap, but it is the only public method on either `Clock` implementation with zero
exercised behavior.

None of the three findings block this session's stated acceptance criterion, and none require
touching out-of-scope files to fix — all three are localized to the files this session already
owns.
