## Assessment (does it work / is it safe / is it worth it)

- **Does it work:** yes, on the evidence above. RED commit (`ec6ed4b`) added a
  failing drill against the pre-existing six-field implementation; GREEN
  (`6ea45e8`) widened the pre-image and nothing else, which is the correct
  minimal fix. Both example-based (`test_rewritten_actor_is_refused`) and
  property-based (P4 fuzz `"actor"` kind) coverage now exist.
- **Is it safe:** yes. The scope is tightly bounded to the stated task —
  `git diff --stat` shows exactly the event-log module, its two test files,
  and doc updates; nothing under `src/`, `main.py`, or `config/config.yaml`
  (the v14 live bot) was touched. The "why now" argument (empty blast radius,
  no deployed log, no pinned hash) is independently verified true, not just
  asserted, and the decision not to build `chain_format_version`/upcaster
  machinery is explicitly reasoned rather than silently skipped.
- **Is it worth it:** yes. This closes a real, previously-identified
  (RS007) provenance gap — an attacker with write access to `events.sqlite3`
  could previously reassign a command's `actor` without detection, which
  directly undermines the §8.5 command-audit story M2 is built on — at
  documented zero cost because it landed pre-deployment.

No out-of-scope files touched, no unjustified new dependency, no silent

explicitly considered and rejected with reasoning, not skipped).
