## Findings

**None actionable.**

I specifically hunted for a reason to reopen this and did not find one. The three
things I tested hardest:

1. **Could the fix be reverted with a green suite?** No — M4 and M1 both die.
2. **Are the round-3 comments accurate?** They make two falsifiable claims and
   both hold (below).
3. **Did the comment commit change behaviour?** No — AST-identical.

**The `age < ttl` comment (`arbiter.py:186-191`) is accurate.** It claims the
purge in `_advance_bar` guarantees the guard is always true, making a mutant that
flips it equivalent rather than an uncovered branch. I instrumented
`_apply_thesis_dedup` and drove every H1/M5 interleaving of 10 bars across 4 TTL
values: of 57,004 sightings, **zero** had `age >= ttl`. The invariant is
structural — after every `_advance_bar(tf)` and every store, all entries under
`tf` have `age < ttl` w.r.t. `_bar_index[tf]`, maintained inductively. The comment
earns its place: it saves the next reviewer that probe.

I also checked the one way that claim could go stale: if `thesis_ttl_bars` were
mutable at runtime, lowering it would leave entries with `age >= ttl` until the
next advance, and the guard would stop being vacuous. It isn't — the GUI's
live-safe key set (`src/ops/web/settings.py:30-32`) covers only
`risk.drawdown_throttle.*`, and `Arbiter` snapshots the value at `__init__`
(`:88`). The claim holds for the shipped system.

**The docstring's quiet-timeframe edge (`arbiter.py:60-68`) is accurate.** It
upgrades the prior "memory concern" framing to "a quiet timeframe *freezes* its
theses". Measured: a thesis seen on M5 is still blocked after 500 H1 bars, entry
retained as `{'Q': ('M5', 0)}`. Its "unreachable today" claim also checks out, and
for a stronger reason than the docstring gives: `_run_strategies` early-returns
before `resolve()` when no strategy matches the closing timeframe
(`system_controller.py:668-670`), and all three configured strategies are H1
(`config.yaml:101,117,136`) — so only one timeframe ever resolves and there is no
second bucket to freeze. The stated reason (one shared tick stream) is also true
for the mixed-arsenal case it is written for.

**The config comment (`config.yaml:63-65`) is accurate** and the value it
annotates is unchanged.

## Non-blocking observations (no action required)

- **The `_UNSET` sentinel is narrower than it looks.** Mutant B8 (`_UNSET` →
  `.get(timeframe)` returning `None`) survives, and it is equivalent for every
  reachable input: `"" != None`, so a first-ever `bar_key=""` advances either way.
  `_UNSET` only earns its keep if `bar_key` is `None`, which `own_token` can never
  be (`str(...)` or `""`, `system_controller.py:679`). This is faithful
  translation of a pre-existing pattern, not something this session introduced —
  recording it only so a future reader doesn't mistake B8's survival for a gap.
  (The round-2 report justified `_UNSET` as guarding `bar_key=""`; that
  justification was wrong, the code is fine, and this file supersedes it.)
- **`TestArbiterTimeframeSeam` asserts kwargs specifically.** Refactoring the call
  site to positional args would fail the test despite being correct. Acceptable —
  kwargs are the convention there — but it is a brittleness, not a behavioural
  assertion.
- **The seam test uses a `RecordingArbiter` stub, not the real `Arbiter`.** There
  is no end-to-end controller-plus-real-arbiter test spanning two timeframes.
  Coverage is nonetheless complete in combination: the stub pins what the
  controller sends (M4, B6 die), and the arbiter unit tests pin what the arbiter
  does with it (M1, M2, M3 die). Not worth a separate test.
- **Pre-existing, unchanged by this diff:** `resolve()` is called once per
  *(symbol, tf)* and `_last_bar_key[tf]` is shared across symbols, so symbols
  whose last closed bar desyncs alternate tokens and over-advance a counter —
  measured `{'H1': 5}` for 2 desynced symbols over 3 real bars. The old global
  counter had the identical property (measured `5`), and the per-timeframe split
  strictly *reduces* spurious advances. Out of scope; noted so it is not mistaken
  for something this diff introduced.
- **Backlog slug is a misnomer** ("FeatureBus" vs the arbiter), recorded only so
  the next reader of `_BACKLOG.md:6` does not go looking in `src/features/`.
- **On the gate's earlier rc=124:** `.mig/config` now sets `VERIFY_TIMEOUT="1200"`,
  and my clean run took 727s wall. That was an orchestrator timeout, never a test
  failure, and it appears already resolved.
