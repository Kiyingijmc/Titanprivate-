   (`assertNotAlmostEqual(effective_risk, 1.5)`) is a sound static proxy for "fails against a
   naive unclamped formula" and satisfies DoD intent. `vol_scalar` range `[0.5,1.5]` enforced

## Findings

**MINOR (non-blocking observation)** — `CountingMode` (`schema.py:143`) declares members
`"n/a"` and `"count"` that are never assigned by any model and have no test coverage: limit #1
is a separate `PerTradeRiskConfig` (not a `LimitRow`) and limit #11 is a plain `int`, so only
`"gross"`/`"net"` are reachable in the current schema. Not a correctness bug — the type stays
valid if a future `LimitRow` needs those modes — just unexercised surface. No action required
this session.

**MINOR (advisory — the doc is the stale side, not the code)** — `pass3-systems.md:432`'s
illustrative prose says the binding-order report prints `"binding limits: #2,#4,#6,#8,#9"`,
whereas `render()` (`schema.py:391-399`) over `_CEILING_COMPARABLE_LIMITS` (`schema.py:350-357`)
would print `#2,#3,#4,#5,#6`. The code is the **correct** side: it deliberately compares only
same-basis raw-risk-at-stop limits (#2–#7) and documents (`schema.py:337-349`) why #8/#9/#10 —
gap-stressed / margin / notional bases — are excluded rather than mislabeled; the doc's prose
both omits #3/#5 (with no stated reason) and includes #8/#9 (a different basis). The DoD only
requires #7 be flagged dead, which is satisfied. Worth a doc fix in a later pass; **no code
change owed by this session.**
