### 4b. `_forced_timezone` correctness

```python
original = os.environ.get("TZ")
os.environ["TZ"] = tz_name
time.tzset()
try:
    yield
finally:
    if original is None:
        os.environ.pop("TZ", None)
    else:
        os.environ["TZ"] = original
    time.tzset()
```

- **Restores on failure as well as success** — the restore is in `finally`, and the `yield` is the
  only statement inside `try`. An assertion failure inside the block still restores. Confirmed.
- **Round-trips a previously-unset `TZ` correctly** — `pop` + `tzset()` re-derives from
  `/etc/localtime`, which is the pre-existing state. Verified empirically with a probe harness that
  snapshots `(os.environ['TZ'], time.timezone, time.tzname)` before and after loading and running
  the module (see §4d).
- **One real ordering hazard, currently latent:** the `os.environ["TZ"] = tz_name` and the first
  `time.tzset()` sit **outside** the `try`. If `tzset()` itself raised, `TZ` would be left mutated
  process-wide. In CPython on Linux `time.tzset()` does not raise for a valid name, so this is
  theoretical — but it is one line from being airtight (`try` should open before the mutation).
  MINOR.
- **`time.tzset()` is Unix-only.** On Windows this module raises `AttributeError` at call time. This
  repo is documented Linux/WSL-only (`CLAUDE.md`), so acceptable — noting it for the record.

### 6a. Does a running bot pick this up? — **No. A restart is required.**

Two independent reasons:

1. **Python does not hot-reload.** The live demo-forward process was started from the pre-fix source;
   its `CandleMaker.process_tick` bytecode is fixed for the life of the process. Nothing short of a
   process restart changes it.
2. **Even at restart, the re-stamp is not incremental — it is total, and that is fine.**
   `GET_HISTORY` is issued **only** from `_perform_warmup` (`system_controller.py:921-931`), which is
   called exactly once, from ignition (`:287`). There is no periodic re-pull. So at the next restart
   the buffer is rebuilt from scratch: 500 M5 + 500 H1 history bars (already UTC, unchanged) plus
   live bars now stamped UTC. **The seam is contiguous from the first restarted bar; there is no
   mixed-clock transitional window and no in-memory migration to perform.**

**Operator action: the fix does not reach the live bot until `main.py` is restarted onto this code.**
Per project memory the demo-forward bot has been running detached since 2026-07-28 on pre-S018 code,
so it is *currently* producing locally-stamped live bars. Restart is the whole remedy.
