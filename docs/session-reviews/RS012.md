## What the diff does

`src/arbiter/arbiter.py`:
- `_bar_index` / `_last_bar_key` become `timeframe -> …` dicts (`:88-91`).
- `_advance_bar(bar_key, timeframe)` (`:154-167`) advances only the arriving
  timeframe's counter and purges only entries stored under it (`tf == timeframe and
  current - idx >= ttl`, `:162-165`). The `_UNSET` sentinel keeps a first-ever
  `bar_key=""` from being read as "same bar".
- `_thesis_memory[thesis]` becomes `(timeframe, index)` (`:188`), and
  `_apply_thesis_dedup` ages a thesis against `self._bar_index[seen_tf]` — the
  counter of the timeframe it was **seen** on (`:179-181`).
- `resolve()` gains `timeframe=""` (`:127`); the default puts every legacy caller
  in one shared bucket, which is the old behaviour exactly.
- Module docstring rewritten to match (`:37-67`).

`src/core/system_controller.py:757`: the single live call site passes `timeframe=tf`.

Rules 2–5, `GRADE_RANK`, `priority`, `Intent`, and the `stats()` shape are
untouched. No clock, no randomness — determinism invariant holds. `_bar_index` /
`_thesis_memory` have no reader outside `arbiter.py` and its tests (grepped `src/`,
`scripts/`, `frontend/`, `tests/`), and `stats()` is unchanged, so GUI/telemetry
surfaces are unaffected.

**The three survivors are equivalent mutants, not coverage gaps.** I did not assume

```

dedup saw an existing entry           : 12600
...of those, with age >= ttl          : 0
```

The reason is structural and worth recording: `_advance_bar` purges an entry the
moment its own timeframe's counter reaches `idx + ttl`, so by the time
`_apply_thesis_dedup` runs, **every surviving entry has `age < ttl` by
construction**. Therefore `age < self.thesis_ttl_bars` (`:181`) is always true, and
the store line (`:188`) is only ever reached with `seen is None`. `B2` and `B4`
mutate lines whose alternate branch is unreachable; `B5` is a relabelling of a
single shared bucket. No test can distinguish them, and none should try.

**Blast radius on the non-live driver:** `src/research/kernel_replay.py:144` drives

refactor is signal-neutral on the only live strategy.

## Non-blocking observations (no action required)

- **`age < self.thesis_ttl_bars` (`arbiter.py:181`) is a redundant guard.** Proven
  above: the purge in `_advance_bar` makes it unconditionally true. It is harmless
  defensive code and I would not ask for it to be removed — removing it would
  couple two rules that are currently independently readable. Recording it so a
  future reader does not mistake the surviving `B2`/`B4` mutants for missing tests.
  A one-line comment at `:181` noting "purge guarantees age < ttl here; this is
  defence in depth" would save the next reviewer the 2048-case probe.
- **A timeframe that goes quiet freezes its theses rather than merely leaking
  memory.** The docstring's "Accepted edge" (`:60-63`) frames arrival-driven
  purging as a *memory* concern. Measured: a thesis seen on M5 is still blocked
  after 500 H1 bars, entry retained as `{'Q': ('M5', 0)}`. Unreachable today (both
  timeframes are driven off the same tick stream, so they go quiet together);
  becomes reachable if a strategy set is ever changed at runtime such that one
  timeframe stops resolving. Worth one clause in that paragraph if it is revisited.
- **`config/config.yaml:63` (`thesis_ttl_bars: 12`) carries no comment**, and its
  meaning changed from "12 global counter ticks" to "12 bars of the thesis's own
  timeframe". No behavioural difference under the current H1-only arsenal; a
  one-line comment will pay for itself when an M5 plugin lands.
- **`TestArbiterTimeframeSeam` asserts kwargs specifically.** A refactor to
  positional args (`arb.resolve(open_positions, own_token, tf)`) would fail the test
  despite being correct. Acceptable — the kwarg form is the convention at that call
  site — but it is a brittleness, not a behavioural assertion.
- **Pre-existing, unchanged by this diff:** `resolve()` is called once per
  *(symbol, tf)* (`system_controller.py:551-557`, `:664`), and `_last_bar_key[tf]`
  is shared across symbols. Symbols whose last closed bar desyncs (missing bars,
  differing session hours) alternate tokens and over-advance a counter — measured
  `{'H1': 5}` for 2 desynced symbols over 3 real bars. The old global counter had
  the identical property and the per-timeframe split strictly *reduces* spurious
  advances (an H1 close no longer masks a same-token M5 close). Out of scope here;
  noting it so it is not mistaken for something this diff introduced.
- **Backlog slug is a misnomer** ("FeatureBus" vs the arbiter). Bookkeeping is the
  orchestrator's; recorded only so the next reader of `_BACKLOG.md:6` does not go
  looking in `src/features/`.
